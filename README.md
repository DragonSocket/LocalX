# P2P TUI Chat (на базе ncat)

Это легковесное приложение для общения в режиме "точка-точка" (P2P) через терминал. В системе **нет центрального сервера**. Каждый участник является автономной единицей: он сам управляет своим сетевым соединением и хранит свою историю переписки.

## 💡 Концепция P2P

- **Нет единого центра**: Общение происходит напрямую между двумя участниками.
- **Локальное хранение**: Каждый пользователь ведет свою базу данных (`chat_<имя>.db`). Ваша история сообщений хранится только у вас.
- **Два режима связи**: Чтобы начать чат, один участник должен запустить приложение в режиме **Хоста** (ожидание), а другой — в режиме **Гостя** (подключение).

## 🛠️ Подготовка

Перед запуском убедитесь, что у вас установлены:

1. **Python 3.12+**
2. **[uv](https://github.com/astral-sh/uv)**: Менеджер пакетов Python.
3. **[ncat](https://nmap.org/ncat/)**: Утилита для управления сетевым соединением (входит в пакет Nmap).

### Установка

1. Клонируйте репозиторий или перейдите в папку проекта.
2. Установите все зависимости с помощью `uv`:
   ```bash
   uv sync
   ```

## 🚀 Как общаться (Инструкция)

Для работы двух людей (например, Алисы и Боба) нужно выполнить следующие шаги:

### Запуск
```bash
uv run python src/main.py
```

---

### Сценарий 1: Общение в локальной сети (разные компьютеры)

**1. Алиса (Хост — тот, кто ждет подключения):**
Запускает приложение и вводит данные:
- **IP Address**: `0.0.0.0` (это заставит программу слушать все сетевые интерфейсы)
- **Port**: `1234`
- **Your Name**: `Alice`

**2. Боб (Гость — тот, кто подключается):**
Запускает приложение и вводит данные:
- **IP Address**: `192.168.1.5` (IP-адрес Алисы в локальной сети*)
- **Port**: `1234` (тот же порт, что у Алисы)
- **Your Name**: `Bob`

*Чтобы узнать свой IP в Linux, введите: `hostname -I`*

- **Port**: `1234`

## 🏗️ Архитектура

Приложение построено по принципу **LEGO** (модульность и Dependency Injection):

- **`Transport` (Network)**: Модуль `NcatManager` управляет подпроцессом `ncat`. Он не знает ничего о базе данных или интерфейсе — он просто передает текст.
- **`Storage` (Database)**: Модуль `SqliteStorage` отвечает только за сохранение и чтение сообщений из локального файла.
- **`View` (UI)**: Интерфейс на `Textual` является "глупым". Он только отображает то, что ему дают, и отправляет события (например, `MessageSent`) наружу.
- **`Controller` (Orchestrator)**: "Мозг" приложения. Он слушает события от UI и говорит: *"Так, сообщение отправлено -> Сохрани его в БД -> Отправь через Ncat"*.

Это позволяет заменить, например, `ncat` на `WebSockets`, не меняя код интерфейса.
