# TUI Chat (на базе ncat)

Асинхронное консольное приложение для чата, построенное на Python. Использует `ncat` в качестве надежного сетевого транспорта и библиотеку `Textual` для создания современного и отзывчивого TUI (Text User Interface).

## 🚀 Особенности

- **Асинхронная архитектура**: Неблокирующий ввод/вывод для сети, базы данных и интерфейса.
- **Модульный дизайн (LEGO-подход)**: Компоненты полностью развязаны через `typing.Protocol`.
- **Сохранение истории**: История переписки автоматически сохраняется в локальную базу данных SQLite.
- **Современный TUI**: Красивый и отзывчивый интерфейс прямо в терминале.

## 📋 Предварительные требования

Перед запуском приложения убедитесь, что у вас установлены:

1. **Python 3.12+**
2. **[uv](https://github.com/astral-sh/uv)**: Высокопроизводительный менеджер пакетов и проектов Python.
3. **[ncat](https://nmap.org/ncat/)**: Часть пакета Nmap. Используется как основной движок передачи данных.

## 🛠️ Установка

1. Клонируйте репозиторий или перейдите в папку проекта.
2. Установите все зависимости с помощью `uv`:
   ```bash
   uv sync
   ```

## 🎮 Использование

Приложение работает в двух режимах: **Сервер** (слушает входящие) и **Клиент** (подключается к серверу).

### 1. Запуск Сервера
Откройте первый терминал и выполните:
```bash
uv run python src/main.py
```
В интерфейсе введите:
- **IP Address**: `0.0.0.0` (чтобы слушать все интерфейсы) или `127.0.0.1`
- **Port**: `1234` (или любой свободный порт)
- **Your Name**: `Server`

### 2. Запуск Клиента
Откройте **второй** терминал и выполните:
```bash
uv run python src/main.py
```
В интерфейсе введите:
- **IP Address**: `127.0.0.1` (IP вашего сервера)
- **Port**: `1234` (тот же порт, что и у сервера)
- **Your Name**: `Client`

Теперь вы можете переписываться между двумя терминалами!

## 🏗️ Архитектура

Проект следует строгим принципам SOLID и модульному принципу "LEGO". Основная логика разделена через **Протоколы (Protocols)**, описанные в `src/interfaces.py`.

- **Протокол `Transport`**: Определяет, как отправлять и получать поток сообщений.
    - *Реализация*: `NcatManager` (обертка над `ncat` через `asyncio.subprocess`).
- **Протокол `Storage`**: Определяет, как сохранять сообщения.
    - *Реализация*: `SqliteStorage` (использует `aiosqlite`).
- **`ChatApp` (View)**: Чистое приложение на `Textual`. Оно отвечает только за отрисовку и реагирует на действия пользователя. Оно ничего не знает о сети или базе данных.
- **`ChatController` (Orchestrator)**: "Клей", который соединяет все модули. Он слушает события от интерфейса и управляет потоками данных между сетью и базой.

Такая архитектура позволяет легко заменять компоненты. Например, вы можете заменить `NcatManager` на `WebSocketManager`, не меняя ни строчки кода в интерфейсе.
