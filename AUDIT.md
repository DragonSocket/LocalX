# AUDIT.md — аудит логики localX

Основано на прочтении всех модулей (`main.py`, `network.py`, `tui.py`, `history.py`,
`config.py`, `env_validator.py`, `exceptions.py`) на коммите `c9ad240`.
Найдено 4 серьёзных проблемы, 7 средних, 8 мелких. Линии указаны по фактическому коду.

---

## 🔴 Высокая критичность

### 1. Офф-бай-о-офф в `_max_scroll()` — Ctrl+Home показывает только 1 строку
**Файл:** `src/ui/tui.py:203-206`

```python
def _max_scroll(self) -> int:
    rows, cols = self._terminal_size()
    return max(0, len(self._wrapped_lines(cols)) - 1)
```

`_max_scroll` должен быть `len(lines) - rows` (чтобы вверху экрана оставался полный экран
старых строк), а не `len(lines) - 1`. При `Ctrl+Home` (`_scroll = _max_scroll()`) из
`total` строк остаются видимыми только `end = total - scroll = 1` строка.
Индикатор `[↑ N]` при этом завышен: PageUp до упора оставляет одну строку сверху.

**Фикс:**
```python
return max(0, len(self._wrapped_lines(cols)) - rows)
```

### 2. `_process_incoming` умирает навсегда при ошибке записи истории
**Файл:** `src/main.py:92-106`

Исключение из `history.append_message()` (например, временный отказ диска,
`HistoryWriteError`) выходит из `async for` и убивает весь consumer входящих сообщений.
Пользователь видит одну строку "incoming stream error" — и больше входящие
сообщения никогда не появляются, хотя транспорт жив.

**Фикс:** оборачивать `append_message` отдельным `try/except` внутри цикла
(логировать и продолжать), либо перезапускать `_incoming_task`.

### 3. `peer_online` и `_known_peers` никогда не очищаются — статус лжёт
**Файл:** `src/core/network.py:88, 110-116, 254-259`

`_known_peers` только пополняется (`add`), никогда не удаляется.
`peer_online = RUNNING and connector is not None and bool(_known_peers)`.
Сценарий лжи:
- пир сделал handshake, затем его listener умер, но наш connector-процесс ещё жив
  (или только что переподключился) → статус "online", хотя peer молчит;
- `/peers` показывает фантомных пиров после disconnect'ов;
- `remote_peer_id` остаётся stale после смерти соединения → статусная строка
  показывает имя несуществующего пира (`src/main.py:187-189`).

**Фикс:** удалять sender_id из `_known_peers` (и сбрасывать `_remote_peer_id`)
в `finally` `_read_stream` или при `proc.wait()` в `_connect_loop`; либо хранить
per-peer timestamp последнего hello и считать online по свежести.

### 4. Обрезка буфера смещает позицию прокрутки
**Файл:** `src/ui/tui.py:270-273`

```python
if len(self._buffer) > MAX_BUFFER_LINES:
    del self._buffer[: len(self._buffer) - MAX_BUFFER_LINES]
```

Если пользователь прокрутил вверх (`_scroll > 0`) и буфер обрезается сверху,
все индексы сдвигаются, а `_scroll` остаётся прежним: вид прыгает,
при `_scroll > новой max_scroll` `_render_transcript` показывает пустоту или
неправильный фрагмент.

**Фикс:**
```python
removed = len(self._buffer) - MAX_BUFFER_LINES
if removed > 0:
    del self._buffer[:removed]
    self._scroll = max(0, self._scroll - removed)
```

## 🟡 Средняя критичность

### 5. `_error_event` установлен, но никем не используется
**Файл:** `src/core/network.py:198` (`self._error_event.set()`), `src/main.py:108-118`

`_connect_loop` сигналит `_error_event` при неудачном подключении, но
`_error_reporter` просто поллит `last_error` каждые 2 секунды. Механизм события —
мёртвый код. Побочный эффект: ошибка появляется в транскрипте с задержкой до 2 с.

**Фикс:** либо `await self._error_event.wait()` в репортере, либо удалить событие.

### 6. `_flush_outbox` не повторяется при частичной неудаче
**Файл:** `src/core/network.py:216, 310-322`

Flush вызывается один раз сразу после connect. Если запись упала (исключение
логируется на `debug`), outbox сохраняется, но повторного flush нет до
следующего переподключения. Сообщения "застревают" до следующего reconnect.

**Фикс:** цикл ретраев внутри `_flush_outbox` или повторный вызов перед каждым
`send_message`, если outbox непустой и connector жив.

### 7. `ncat -l -k` расширяет сообщения всем подключённым — семантика "один peer" не соответствует транспорту
**Файл:** `src/core/network.py:139-143`

Listener с `-k` ретранслирует stdin всем клиентам. При 3+ инстансах сообщения
расходятся broadcast'ом (это уже групповой чат), но логика `peer_online`,
`remote_peer_id` и статусной строки рассчитана на ровно одного пира.
`/peers` — единственный честный индикатор мульти-соединений.

**Фикс (если нужен именно P2P):** документировать поведение multicast,
или показывать в статусе число handshake'ов.

### 8. Один peer_id на двух инстансах → самоподавление сообщений
**Файл:** `src/core/network.py:249-251`

Если два запущенных инстанса настроены с одинаковым `[node] peer_id`, все их
сообщения отбрасываются как self-echo. Дефолтный `peer_id = USER`
(`src/core/config.py:115`) усиливает риск: два инстанса одного пользователя
молчат друг другу.

**Фикс:** предупреждение при обнаружении своего sender_id в входящем потоке,
или уникальный suffix (pid/uuid) в дефолте.

### 9. Мёртвый код в `history.py`
**Файл:** `src/core/history.py:33` (`self._lock = threading.Lock()` — не
используется нигде), `src/core/history.py:87-88` (`_batch_size()` — не
вызывается). Двусмысленность между двумя замками вводит в заблуждение при
будущем рефакторинге.

### 10. `/history` парсит аргумент некорректно
**Файл:** `src/main.py:68-75`

- `/history -5` → `parts[1] = "-5"`, `.isdigit()` False → count = 20 (тихо);
- `/history 100000` читает весь файл в память (`load_history` делает
  `f.readlines()` + list-comprehension).

**Фикс:** валидировать int с границей (например 1..500), streaming tail.

### 11. `EnvironmentValidator` сравнивает версии по списку int
**Файл:** `src/core/env_validator.py:45-55`

`re.findall(r"(\d+\.\d+)")` берёт первое число вида `X.Y`. Для `Ncat 7.98` —
корректно. Но `7.10 < 7.9` в списочном сравнении `[7,10] < [7,9]` → ложный
успех/провал на будущих версиях. Требуется `7.0` — сейчас не критично.

## 🔵 Низкая критичность / замечания

### 12. Последние входящие сообщения теряются при остановке
**Файл:** `src/core/network.py:233` (цикл `_read_stream` выходит, когда
`_state != RUNNING`) против `network.py:330` (`listen()` ещё 1 с вытягивает
очередь). После перехода в STOPPING новые строки из stdout ncat уже не
парсятся: сообщения, пришедшие в момент выхода, пропадают.

**Фикс:** короткий drain `_read_stream` после SIGTERM (1–2 с) перед выходом.

### 13. `LOG_FILE` и `config.toml` привязаны к cwd
**Файл:** `src/main.py:16` — `Path("logs") / "localX.log"`. Запуск из другой
директории создаёт логи там; `config.toml` тоже резолвится относительно cwd
(`config.py:58-59` через `.resolve()`). История и настройки "расъезжаются"
при запуске не из корня проекта.

**Фикс:** базировать пути на `Path(__file__).parent.parent` или принимать
`--config`/`--log-dir` аргументами.

### 14. `NetworkProcessError` — объявлена, но нигде неraising
**Файл:** `src/core/exceptions.py:33`. Ни один raise в коде. Мёртвый класс,
раздувает API исключений.

### 15. Outbox переполнен при офлайне — исключение вместо graceful-поведения
**Файл:** `src/core/network.py:292-295`. После 200 накопленных сообщений
`send_message` бросает `NetworkInvalidStateError` (не `NetworkConnectionError`,
семантически неверный тип). Пользователь видит ошибку в транскрипте, но
контекст "что делать" отсутствует.

### 16. `_reconnect_delay` фиксирован — нет backoff
**Файл:** `src/core/network.py:199` — `asyncio.sleep(self._reconnect_delay)`
(5 с) без экспоненциального роста. При длительном офлайне пира это допустимо,
но при flap'сетях (обрыв каждые 6 с) reconnect-шум занимает логи и CPU.

### 17. `_flush_outbox` пишет весь outbox одним блоком
**Файл:** `src/core/network.py:315` — `"".join(...)` одной write-операцией.
Для 200 сообщений это нормально, но при большом outbox и медленном канале
возможна частичная запись с потерей хвоста без подтверждения.

### 18. `/peers` не имеет статуса "кто реально жив"
**Файл:** `src/main.py` (команда `/peers`) опирается на `_known_peers`,
которая бесконечна и не очищается (см. пункт 3). Команда не выполняет свою
функцию — показывает исторический список всех, кто когда-либо handshake'нулся.

### 19. Статусная строка построена на `config`, а не на фактическом состоянии
**Файл:** `src/main.py:52-58, 187-189` — показывает `config.node.peer_id` и
 configured host:port даже после reconnect'ов на другие адреса (например,
если remote слушает на другом порту в той же сети). Мелкое несоответствие
между "настроено" и "фактически подключено".

## Порядок исправлений (рекомендация)

1. **#1 `_max_scroll`** — однострочный фикс, заметный UX-эффект сразу.
2. **#2 try/except вокруг `append_message`** — защита от смерти consumer.
3. **#3 очистка `_known_peers` / timestamps hello** — честный статус и `/peers`.
4. **#4 корректировка `_scroll` при обрезке буфера** — стабильность прокрутки.
5. **#5/#9/#14** — удаление мёртвого кода (`_error_event`, `_lock`,
   `_batch_size`, `NetworkProcessError`).
6. Остальное — по мере необходимости, обратная совместимость не страдает.
